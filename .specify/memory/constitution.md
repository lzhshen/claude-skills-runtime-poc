# Claude Skills Runtime PoC 项目宪法

## 核心原则

### I. 简单可依赖

每个设计决策必须优先考虑简单性和可靠性，而非灵活性或可扩展性。

- **不引入不必要的复杂度**: 不引入当前功能不直接需要的抽象、模式或间接层
- **YAGNI (你不会需要它)**: 不为假设的未来需求构建功能；只实现当前需要的
- **直接的解决方案**: 优先选择直接的实现，而非巧妙或花哨的方案
- **最小依赖**: 每个外部依赖必须证明其必要性；优先使用标准库方案
- **可删除的代码**: 代码应该易于删除；避免导致删除困难的紧耦合

**理由**: 复杂系统更难理解、调试和维护。简单性降低认知负担，加速开发，提升长期可维护性。可靠的系统是可预测的系统。

### II. 测试驱动开发 (TDD)

所有功能实现必须遵循 TDD 纪律: 红 → 绿 → 重构。

- **测试先行**: 测试必须在任何实现代码编写之前编写并验证失败
- **最小实现**: 只编写足够让失败测试通过的代码
- **绿灯后重构**: 重构只允许在测试通过后进行；重构不得改变行为
- **无未测试代码**: 每个功能、bug 修复或行为变更必须有相应的测试
- **测试独立性**: 测试必须独立隔离；测试之间不共享可变状态

**理由**: TDD 通过设计确保代码正确性，提供活文档，支持无畏重构，立即捕获回归。测试先行的纪律迫使我们清晰思考需求和接口。

- 本宪法优先于本项目中的所有其他开发实践
- 所有代码变更必须遵守这些原则
- 修订需要:
  1. 明确的理由说明为何需要变更
  2. 按照语义化版本规则递增版本号

- 复杂度违规必须在设计文档中明确说明理由（参见 plan 模板中的复杂度追踪）
