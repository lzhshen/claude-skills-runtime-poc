# 功能规格说明：Claude Skills 运行时框架与测试 Web 应用

**功能分支**: `003-skills-runtime`
**创建日期**: 2026-01-08
**状态**: 草稿
**输入**: 用户描述："为 claude skills 智能体实现一个运行时框架和测试web app，web app 支持 claude skills zip 包上传、内容检验（必须符合 claude skills 规范）、目录树和文件内容预览、内容修改和重新打包；claude skill 运行、运行日志和结果查看等；claude skills 运行时框架基于 opencode + oh-my-opencode 构建"

## 用户场景与测试 *（必填）*

### 用户故事 1 - 上传并验证技能包（优先级：P1）

作为技能开发者，我希望上传 Claude Skills zip 包并自动根据 Claude Skills 规范进行验证，以便在测试之前快速识别技能中的任何问题。

**优先级说明**：这是整个应用的基础。没有上传和验证技能的能力，其他功能都无法运行。这是所有用户工作流程的入口点。

**独立测试**：可以通过上传各种有效和无效的技能包来完整测试，验证结果是否准确且可操作。

**验收场景**：

1. **假设**我有一个有效的技能 zip 包，**当**我通过 Web 界面上传时，**那么**系统会解压内容，验证 SKILL.md 文件是否存在且具有正确的 YAML 前置元数据（name 和 description 字段），并显示成功消息和技能元数据。

2. **假设**我有一个缺少 SKILL.md 的 zip 包，**当**我上传时，**那么**系统会显示清晰的错误消息，指出"需要 SKILL.md 文件"并建议纠正措施。

3. **假设**我有一个 YAML 前置元数据无效（缺少 name 或 description）的技能，**当**我上传时，**那么**系统会显示具体的验证错误，列出缺少哪些必填字段。

4. **假设**我上传的文件不是有效的 zip 压缩包，**当**上传完成时，**那么**系统会显示错误消息，指出文件格式无效。

---

### 用户故事 2 - 浏览和预览技能内容（优先级：P2）

作为技能开发者，我希望查看已上传技能包的目录树和文件内容，以便在不下载的情况下了解技能结构并审查其内容。

**优先级说明**：技能上传后，用户需要在运行或修改之前检查其内容。这对于理解和调试技能至关重要。

**独立测试**：可以通过上传包含多个文件和目录的技能包来完整测试，然后导航树形视图并打开文件以验证内容是否正确显示。

**验收场景**：

1. **假设**我已上传一个有效的技能包，**当**我查看技能详情页面时，**那么**我会看到一个交互式目录树，显示包中的所有文件和文件夹。

2. **假设**我正在查看目录树，**当**我点击一个文件时，**那么**文件内容会显示出来，并对 markdown 和 YAML 文件进行适当的语法高亮。

3. **假设**我正在查看一个文件，**当**该文件是 SKILL.md 文件时，**那么**YAML 前置元数据会被解析并以结构化格式显示，同时显示原始内容。

---

### 用户故事 3 - 编辑并重新打包技能（优先级：P3）

作为技能开发者，我希望直接在 Web 界面中修改技能文件并下载更新后的 zip 包，以便无需使用外部工具即可快速修复。

**优先级说明**：这使得无需离开 Web 界面即可快速迭代技能。它建立在预览功能（P2）的基础上，并添加了编辑能力。

**独立测试**：可以通过上传技能、修改 SKILL.md 内容、重新打包并验证下载的 zip 包含更改来完整测试。

**验收场景**：

1. **假设**我正在查看技能包中的文件，**当**我点击"编辑"时，**那么**我可以在带有语法高亮的文本编辑器中修改文件内容。

2. **假设**我已对一个或多个文件进行了更改，**当**我点击"保存"时，**那么**更改会在会话中保留，文件树会指示哪些文件已被修改。

3. **假设**我已修改技能包中的文件，**当**我点击"重新打包并下载"时，**那么**会生成一个包含所有原始文件和我的修改的新 zip 文件，下载会自动开始。

4. **假设**我有未保存的更改，**当**我尝试离开页面或上传新包时，**那么**系统会提示我先确认或保存更改。

---

### 用户故事 4 - 使用 opencode 运行时运行技能（优先级：P4）

作为技能开发者，我希望使用 opencode 运行时执行我上传的技能，以便测试技能在真实环境中的表现。

**优先级说明**：这是核心测试功能。它依赖于上传/验证（P1）完成，并受益于预览（P2）和编辑（P3）功能。

**独立测试**：可以通过上传有效技能、提供测试提示、执行技能并观察输出是否符合预期行为来完整测试。

**验收场景**：

1. **假设**我已加载一个经过验证的技能包，**当**我导航到"运行"选项卡时，**那么**我会看到一个用于输入测试提示的输入框和一个"运行技能"按钮。

2. **假设**我已输入测试提示，**当**我点击"运行技能"时，**那么**系统会启动与 opencode 运行时的会话，注入技能指令，并开始处理提示。

3. **假设**技能正在运行，**当**执行进行中时，**那么**我会看到实时进度指示器，并可以在需要时取消执行。

4. **假设**技能执行完成，**当**我查看结果时，**那么**我会看到 AI 智能体的完整响应，包括任何工具调用。

---

### 用户故事 5 - 查看执行日志和结果（优先级：P5）

作为技能开发者，我希望查看技能运行的详细执行日志和结果，以便调试问题并了解技能的表现。

**优先级说明**：这补充了运行功能（P4），提供可观察性和调试能力。

**独立测试**：可以通过运行具有已知行为的技能并验证日志是否捕获所有预期事件、工具调用和响应来完整测试。

**验收场景**：

1. **假设**技能已执行，**当**我查看执行结果时，**那么**我会看到完整的对话历史，包括系统提示、用户提示和 AI 响应。

2. **假设**技能执行包含工具调用，**当**我查看日志时，**那么**我会以结构化格式看到每个工具调用及其参数和结果。

3. **假设**已发生多次技能执行，**当**我查看执行历史时，**那么**我会看到过去运行的列表，包含时间戳、状态（成功/错误），并可以点击查看详情。

4. **假设**执行结果出现错误，**当**我查看错误详情时，**那么**我会看到错误消息、堆栈跟踪（如果有）以及执行失败的位置。

## 需求 *（必填）*

### 功能需求

**技能包管理**

- **FR-001**：系统必须接受包含 Claude Skill 包的 zip 文件上传，最大 10MB
- **FR-002**：系统必须解压上传的 zip 文件并验证在根目录或单个顶级目录中是否包含 SKILL.md 文件
- **FR-003**：系统必须解析并验证 SKILL.md 中的 YAML 前置元数据，确保必填字段（name、description）存在
- **FR-004**：系统必须显示验证结果，对任何失败提供清晰、可操作的错误消息
- **FR-005**：系统必须提供解压包中所有文件的层级目录树视图
- **FR-006**：系统必须显示文件内容，对 .md、.yaml 和 .yml 文件进行语法高亮
- **FR-007**：系统必须允许用户直接在浏览器中编辑文件内容
- **FR-008**：系统必须跟踪已修改的文件，并在目录树中以视觉方式指示更改
- **FR-009**：系统必须从当前状态（包括所有修改）重新生成有效的 zip 包
- **FR-010**：系统必须优雅地处理二进制文件，将其显示为不可编辑并提供文件大小信息

**技能执行运行时**

- **FR-011**：系统必须通过 opencode SDK 与 opencode 服务器集成以执行技能
- **FR-012**：系统必须为每次技能执行创建隔离的会话
- **FR-013**：系统必须将 SKILL.md 中的技能指令注入 opencode 会话上下文
- **FR-014**：系统必须接受用户提示作为技能测试的输入
- **FR-015**：系统必须将执行进度和响应实时流式传输到用户界面
- **FR-016**：系统必须捕获并存储完整的执行日志，包括工具调用和响应
- **FR-017**：系统必须强制执行每次运行最长 5 分钟的超时
- **FR-018**：系统必须允许用户取消正在运行的执行

**执行历史和日志**

- **FR-019**：系统必须为当前会话保留执行历史
- **FR-020**：系统必须显示执行历史，包含时间戳、技能名称、状态和持续时间
- **FR-021**：系统必须提供详细的日志查看，以结构化方式显示工具调用
- **FR-022**：系统必须在执行失败时捕获并显示错误信息

### 关键实体

- **SkillPackage（技能包）**：表示已上传和解压的技能包；包含包 ID、原始文件名、解压路径、验证状态、验证错误、文件列表和上传时间戳

- **SkillFile（技能文件）**：表示技能包中的单个文件；包含文件路径、内容（对于文本文件）、文件类型、修改状态和原始内容哈希

- **SkillMetadata（技能元数据）**：表示解析后的 SKILL.md 元数据；包含名称、描述和原始 markdown 内容

- **ExecutionSession（执行会话）**：表示单次技能执行运行；包含会话 ID、技能包引用、用户提示、开始时间、结束时间、状态和结果

- **ExecutionLog（执行日志）**：表示执行的日志条目；包含日志 ID、会话引用、时间戳、日志类型（消息/工具调用/错误）和结构化内容

## 成功标准 *（必填）*

### 可衡量的结果

- **SC-001**：用户可以在 30 秒内上传、验证和预览小于 5MB 的技能包
- **SC-002**：验证能够 100% 正确识别缺少必需的 SKILL.md 或前置元数据字段的包
- **SC-003**：用户可以在 60 秒内完成简单编辑并下载重新打包的技能
- **SC-004**：技能执行结果在开始运行后 5 秒内开始流式传输给用户
- **SC-005**：95% 的技能执行在没有系统错误的情况下成功完成（不包括技能逻辑错误）
- **SC-006**：执行日志捕获所有工具调用的完整请求/响应数据
- **SC-007**：用户能够在 90% 的情况下从错误显示中识别技能执行失败的原因
- **SC-008**：Web 应用在标准连接下 3 秒内加载并变为可交互状态

## 假设

- opencode 服务器已部署并可从 Web 应用后端访问
- 用户对 Claude Skills 格式和 YAML 语法有基本了解
- 初始版本单用户会话即可满足需求（无需多用户协作）
- 技能包遵循标准 Claude Skills 格式，以 SKILL.md 作为主要定义文件
- Web 应用将通过现代浏览器访问（Chrome、Firefox、Safari、Edge - 最新 2 个版本）
- 初始版本的会话数据和执行历史无需在浏览器会话之外持久化
